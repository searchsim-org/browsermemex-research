# LongMemEval-S retrieval adapter: protocol before first execution

Use the entire public `longmemeval_s_cleaned.json` (500 questions) downloaded from the official author's Hugging Face dataset. Preserve its input SHA-256. Index each history session as an EpisodicEvent, preserving its text, session identifier, timestamp and provenance. This is a pass-through session adapter, not an LLM atomic-fact extractor. Strip `has_answer` annotations and never index question, expected answer or evidence IDs. No truncation and no query-dependent ingest selection. Each question receives an isolated store.

Use the actual NuggetStore and SQLite WASM. Compare its no-expiry session retrieval with fixed 7/30/90-day expiry policies implemented by the same FTS5 query and interval predicate. Also test exact parity with a matched unexpired temporal BM25 query. No dense, graph or generative-answer performance claim. Query tokens are the original question; top-10, with Recall@5 and @10 and all-evidence-found at 10. Gold labels are the original `answer_session_ids`, used only by the scorer. Exclude abstention questions (IDs ending `_abs`) from evidence recall, following the upstream protocol, while retaining their retrieval outputs. Do not infer abstention correctness from retrieval alone.

Session timestamps after question time are ineligible for all policies. Parse the supplied date strings explicitly as UTC; reject missing/invalid dates. Report invalid records, exclusions and exceptions. Aggregate macro recall by question, and category slices; paired bootstrap across non-abstention questions gives 95% intervals conditional on this fixed benchmark. Do not use these intervals to claim a population of real users. Release per-question retrieved IDs and evidence IDs, dataset hash and adapter. Raw upstream data retain their MIT license; the generated local synthetic dataset's license does not supersede upstream terms.

## Protocol addendum, after date audit and before provided-history run

The first run and its outputs remain unchanged. A date audit found 44 questions with labeled evidence dated after question time. Consequently the causal restriction changes evidence availability relative to the upstream supplied-context retrieval task. A second, explicitly named `--provided-history` run will index every provided session, retaining event timestamps in provenance and `created_at`. In that run source sessions are treated as available input regardless of date (validity start 0); fixed TTL controls filter original event age against question date and also retain future-dated provided context. No expiry retrieves exactly the matched BM25 result by construction. This second run assesses the upstream provided-history retrieval interface, not a causal temporal benchmark or a model QA score. Report the date inconsistency and retain both runs; do not compare their scores as if the admissible evidence were identical. No query text, ranking algorithm, thresholds or benchmark labels are changed.
