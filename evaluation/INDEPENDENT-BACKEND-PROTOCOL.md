# Independent retrieval backend protocol

Recorded before executing the independent adapter, 2 November 2026. Established third-party backend: `rank-bm25==0.2.2`, Apache-2.0, `BM25Okapi` with upstream defaults k1=1.5, b=0.75, epsilon=0.25. Official implementation and preprocessing documentation: https://github.com/dorianbrown/rank_bm25 . The package receives token lists and does not supply preprocessing itself. Pin NumPy1.23.3 to match the existing Python environment.

Use all 40 unchanged saved BMTR worlds, five seeds, two interval settings and four corruption levels. The index receives only observations available at each query's knowledge time. Index only canonical subject/predicate/observed-value text, matching the existing FTS5 control, with lowercase Unicode letter/digit tokenization. No truth ledger, expected answer, corruption label or true expiry is supplied to the backend. Rebuild the independent index at each of the three knowledge-time checkpoints rather than fitting or updating parameters from answers.

Run three rank-bm25 methods: lexical ranking without interval filtering, lexical ranking with supplied interval filtering, and interval filtering with newest-effective-start/observation tie order. Corpus statistics use all observed documents, including expired ones, matching the FTS corpus. Apply eligibility filters before top10 and preserve lexical OR candidate semantics (at least one query token). Stable insertion order resolves ties in the first two methods; the recency method breaks exact score ties by effective start and observation time, then observation ID. Score ranking using the existing deterministic exact subject/predicate resolver and identical answer/null and evidence-presence definitions. Retain per-query predictions, gold for scoring only, evidence counts, selected IDs and scores.

Report answer-or-abstention accuracy, wrong-answer fraction, coverage and gold-presence recall on answerable queries, aggregated within each world then mean/Student-t95% intervals across five worlds. Compare saved FTS5 controls and actual WebNugget under the same metadata/worlds. Differences can arise from independent BM25 formula/IDF smoothing, tokenization and ranking, not just lifecycle rules. This is an independent lexical implementation comparison, not an evaluation of hosted memory services, temporal graphs, neural representations, LLM extraction or answer generation. No model calls or token costs occur. Do not compare Python wall time with Node as a retrieval-system efficiency claim.

Record source/package/protocol/script hashes, Python/NumPy versions and all40 input hashes. Preserve existing outputs. Independently recount totals and summary metrics from output records after execution.
